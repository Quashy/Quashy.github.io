# 从桌面养猫到一句话记账：我的三个 Personal Agent 小实践

![小黑拉开以对话气泡作把手的抽屉，查看猫、读书笔记和账单，边用边改自己的小工具](/three-small-projects/04-conversation-drawer-cover.png)

> 最近 Personal Agent 比较火，Muse 属于是来晚了，我是先用上了 ChatGPT Dot。最近也在做 wolai -> Notion 的迁移，根据自己的生活习惯做了一些基于 Notion 的小实践，一开始都是自己想用。做着做着也开始思考是不是可以做成标准化产品推广给别人用、项目介绍怎么写，以及分享一些 AI 时代下对于传统软件的思考。

## 0x00 起因

熟悉我的朋友应该知道我已经用了 wolai 三年多了，主要作为日记本和生活记录。当初选择的 wolai 的原因是因为 Notion 还没有支持简中，并且受限于网络访问等等原因吧，选择了国产版 Notion，也就是 wolai。但是这么些年下来 Notion 不断完善，而 wolai 几乎也没有什么太大的更新了，并且生态封闭，渐觉后悔当初的选择。遂有了 wolai 向 Notion 的迁移计划。

![wolai 个人专业版订阅记录](/three-small-projects/05-wolai-subscription-history.png)

![个人知识库的工作、学习、生活和归档目录](/three-small-projects/06-personal-notebook-structure.png)

Personal Agent 我是很认可的，产品包括有 ChatGPT Dot（Pro可用）、Grok Bot（首月15刀）、Muse（免费），相当于有一个 AI 助手来帮你打点你的一切生活琐事，你只需要用自然语言交代需求，Agent 负责判断、理解、生成，并且天然很适合 Notion 这样的云端笔记，因为可以跑在云端环境里。Obsidian 这样的本地笔记的话 Personal Agent 就只能跑在本地了，需要电脑一直不关机。其实已经好久没用 Obsidian 了。

我也一直在探索人生 ALL IN ONE，之前觉得是有强大插件系统的 Obsidian，再后来是可以轻松和大家协作、分享页面的 wolai，AI 时代我想把答案给到带有 CLI/MCP 的 Notion。

接下来分享一些我自己做的实践小项目和感受思考。

## 0x01 披萨宠物

第一个项目的主角是我和我对象的猫，披萨。Codex 的虚拟宠物功能用很久了，我想把它放到桌面上，于是做了写实风格和 16-bit 像素风格的桌宠。

![小黑把自己的猫照片做成写实桌宠和 16-bit 像素桌宠，像素版使用 128×128 逻辑画布](/three-small-projects/01-pizza-cat-variants.png)

不难，就是发一张自己宠物的照片给 AI，让 AI 做就好了，做完披萨，我又想，别人拿一张自己宠物的照片，能不能也用一条指令做出自己的桌宠？

于是我把制作过程整理出来，让 Agent 知道拿到照片以后该怎样生成角色和动作，再把做好的宠物交给用户。这样别人也可以拿自己的猫狗照片来做桌宠。

我也把自己的 Dot 换成了 Pizza：

![披萨作为 Dot 头像的资料页，显示联络入口和电脑就绪状态](/three-small-projects/07-pizza-dot-profile.png)

项目放在 [pizza-cat-pets](https://github.com/Quashy/pizza-cat-pets)，里面也整理了这套制作方式。

想先把披萨领到桌面上，可以把下面这段话复制给 AI：

```text
请按下面的指南，帮我把写实版和像素版披萨都装好，先启用像素版：
https://raw.githubusercontent.com/Quashy/pizza-cat-pets/main/prompts/install.md
```

## 0x02 微信读书 × Notion

第二个项目是因为最近在看《日本蜡烛图技术：古老东方投资术的现代指南》，调研过多个开源阅读器，考虑到多端阅读的便捷性、可维护性、阅读体验还是放弃了一些第三方书籍阅读器，微信读书就挺好的，阅读体验独一档，并且也支持导入书籍。

从一个很具体的问题开始：在微信读书里看到一段有用的话，顺手就能划线、写下想法，但过一段时间想起来，又要回去翻那本书。我想继续照常用微信读书，也想把笔记放到 Notion，方便整理和回顾。

于是结合了一下自身情况，既然都用 ChatGPT Dot 了，也能通过 CLI/MCP 的形式访问 Notion，而恰好微信读书也有 skill，那是不是都可以打通呢？以此来建立专属于自己的图书馆。

所以我在开源项目的基础上继续做了 [weread2notion-AI](https://github.com/Quashy/weread2notion-AI)，通过 GitHub Actions 同步书架、阅读进度、划线、想法与统计，在 Notion 里查看和回顾。阅读留在微信读书里，积累下来的内容则能在 Notion 继续整理。

![微信读书的划线与想法自动同步到 Notion，按需与 Agent 讨论后关联保存独立心得](/three-small-projects/02-weread-notion-reading-notes.png)

有时候我还想围绕某条笔记继续聊，就可以直接和 ChatGPT Dot 聊天，让它读我选中的笔记，和我讨论，再把整理后的心得写到 Notion 的心得区域，和原来的笔记关联起来。

想搭一个自己的 Notion 图书馆，也可以把这段话复制给 AI：

```text
请按下面的指南，帮我搭建微信读书 → Notion 图书馆：
https://raw.githubusercontent.com/Quashy/weread2notion-AI/main/docs/AI_SETUP.md
```

## 0x03 AI × Notion 财务系统

第三个项目是记账，我有朋友一直有良好的记账习惯，耳濡目染之下我也想要开始记账了，但是我又是一个受不了繁杂琐事的人，打开软件，填写金额填写分类选择账本选择钱包，在干饭一秒都不能耽误的场景下，我是受不了一点，那 Personal Agent 这么方便，能不能用 AI 来帮我们记账呢？

所以按照上面微信读书的思路，把 Agent 作为人和账本的中间层，人只需要打开软件点击语音输入，中午吃了麦当劳 1+1 随心配 14.9 元，Agent 负责理解、判断、归类账本、写入账本、汇报结果给你。完全把人从复杂软件界面操作解放出来。

项目地址 [notion-finance-ai](https://github.com/Quashy/notion-finance-ai)。

我通常就用语音输入，用一句话交代发生了什么，由 Agent 拆分记录、分类、核对，再写入账本。午饭只有一笔支出，遇到退款和重新购买，也是直接语音输入交给强大的 Agent 来理解去记账就行了。

比如原车票 300 元，全额退款到账后又买了一张 420 元的新票，净车票支出是 `300 - 300 + 420 = 420` 元。账本里会保留原来的支出、对应的退款和新支出，留痕。

在这个例子里，Agent 会通过 Notion 的 CLI/MCP 找到退款对应的原支出，保留原记录，再记下新票支出。写入以后再读一次账本，确认记录和交代的情况一致。

除了随手记账，我还可以设置一次周报任务，交代统计范围和执行时间，由支持调度的 Agent 到点自动读取账本，整理好周报主动推送。任务设好以后，到了约定时间就能收到结果，平时如果想查看或核对账目，打开 Notion 自己看就可以了。

![一句话记账后在 Notion 查看；设置一次任务，由支持调度的 Agent 到点送来周报](/three-small-projects/03-agent-bookkeeping-weekly-report.png)

记账时把事情说清楚，平时打开账本查看，每周再收到一份整理好的财务报告。

想试试一句话记账，可以先把下面这段话复制给 AI，搭好自己的账本：

```text
请按下面的指南，帮我把 Notion 账本搭好：
https://raw.githubusercontent.com/Quashy/notion-finance-ai/main/docs/AI_SETUP.md
```

## 0x04 做完这三个项目，我想了三件事

### 自然语言对话或许是下一代软件入口

现在软件的入口，我觉得已经从传统的界面变成 AI 对话式了，属于是一旦用过一次就回不去原来的各种软件的复杂界面自行操作的模式了，Personal Agent 可以配合 Notion 等笔记类软件用 AI 管理知识、日记、财务，甚至可以做到商业级 CRM 系统的效果。要做的只需要打通各软件之间的壁垒。

### 模型能读更多，人不一定愿意读更多

想要做好一个软件一定要从用户、软件使用者的角度出发。

AI 时代下，各家 LLM 的注意力与上下文窗口在无限变强与放大，人的注意力是有限的，也容易变得越来越没有耐心。

推广一个产品的情形下，一定要从用户使用者的角度出发，用示例、图表、流程图等等方式，直观让他感受到，使用了之后可以解决他什么样的问题，以及能够达到什么样的效果。

功能做完以后，我又花了不少工夫改项目介绍。别人第一次打开仓库，要先看明白这个项目和自己有什么关系，才会决定要不要继续读。

### 软件工程还要考虑，软件能不能被 Agent 用好

这几个项目也让我重新看待文档。

README 要让人看懂项目、知道怎么开始用；给 Agent 的则要把配置和操作交代清楚，让它读完就能动手。

软件的使用者现在不仅仅是人类，CLI/MCP/Skill 等等方式，让软件越来越容易被集成到已有的系统和 AI Agent 中，下次再做产品做功能不妨想想，你的软件可以很好的被接入 AI

做完这三个项目以后，下次做软件，我会先问什么？
